# Contributing

Read the [development guide](docs/development.md) and keep changes focused.
Describe the problem, resulting behavior and relevant validation in each PR.

Preserve API/platform compatibility and security invariants. Include regressions
for meaningful behavior changes. Run repository checks, formatting, tests and
Clippy before requesting review; platform CI covers native contracts.

Use synthetic configurations and public test fixtures. Remove personal paths,
addresses, account tokens, keys and captures from reports. Configure Git to use
your GitHub-provided private commit email if you do not want an email published.

Report vulnerabilities through the [security process](SECURITY.md), rather than
posting sensitive details in a public issue. Contributions are licensed under
the project's existing license; retain required upstream notices.
